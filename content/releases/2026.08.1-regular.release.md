# 2026.08.1-regular

## Summary

Initial release of Visit-Counter, a GitHub-native repository view counter built
as a containerized Rust action. It reads GitHub's Traffic API, preserves daily
history, renders the bundled counter artwork, and publishes a self-contained
GIF without an external counter server.

## Notable Changes

- Add the Rust traffic collector and GIF renderer as a Docker-based GitHub
  Action.
- Merge GitHub's overlapping daily traffic windows without double-counting and
  retain older daily records in `history.json`.
- Bundle the initial animated `0` through `9` counter artwork and compose the
  selected digits into the generated GIF.
- Add an hourly and manually dispatchable workflow that publishes
  `history.json` and `views.gif` to the automation-owned `visit-counter`
  branch.
- Provide a copyable `.github` package under `src/` containing the consumer
  workflow and its local action implementation.
- Validate the Rust action through its locked Docker build alongside repository
  and publication checks.

## Issues Addressed

- Replaces the external visitor-counter dependency inherited from the repository
  template.
- Establishes a GitHub-hosted response path at
  `https://OWNER.github.io/REPOSITORY/visit-counter/views.gif`.
- Prevents repeated hourly runs from adding the same rolling Traffic API window
  more than once.

## Compatibility

The action runs on GitHub-hosted Linux runners with Docker support. A target
repository must provide a fine-grained `PERSONAL_RELEASE_TOKEN` with repository
Administration read permission. The workflow uses its separate `GITHUB_TOKEN`
with `contents: write` only to publish the generated counter branch.

The all-time total represents repository views. Daily unique counts are stored
but are not summed into an inaccurate all-time unique-visitor total.
